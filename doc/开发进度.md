## 2026-11-28：1.6.2

| 模块 | 内容 |
|---|---|
| ProjectRed 检测 | GTNH 的 ProjectRed Transmission 线缆是 ForgeMultipart 部件，方块本体为多方块代理方块，不触发 `BlockRedstoneEvent`；改为监听 `BlockPhysicsEvent`，按 `getChangedTypeId()` 是否等于运行期解析出的代理方块 ID 过滤，再在触发点六邻面内定位承载线缆的 `TileMultipart` |
| 计数与阀值 | 单坐标 `ProjectRed.Limit`、单区块 `ProjectRed.ChunkLimit` 两级判定；区块合计超限时用该区块计数最高的坐标定位，避免大范围线缆网络把事件摊薄而漏检 |
| 没收 | 反射 `TileMultipart.remPart(TMultiPart)` 逐个移除 `WirePart` / `FramedWirePart`，线缆全部移除后代理方块自动变空气；配置未装 ProjectRed 时该分支静默停用 |
| 没收爆炸 | 新增 `RedStone.Explosion` 段：没收成功后在该位置生成一次爆炸，默认威力 10.0（TNT 为 4.0）；是否引燃、是否破坏方块、单周期次数上限均可配。插件自身发起的爆炸通过 `CheckRedstone.pluginExplosion` 标志让 `AntiExplode` 放行 |
| 公告 | ProjectRed 路径使用独立的 `RedStone.ProjectRed.Message`，未配置时回退到 `RedStone.Message`；广播文案同时写一条日志，便于无人在线时核对。**公告只说明线缆被清理，不提示爆炸**——本服装有 ServerUtilities，爆炸表现由其接管；爆炸生成记录降为 FINE 级日志 |
| 逻辑门检测 | 新增 `RedStone.Gate` 段（`Enable` 默认 false / `Limit` 600 / `ChunkLimit` 1800 / `Message`）。`RedstoneGatePart.notifyExternals` 在输出变化时对周围坐标调用 `World.func_147460_e`，与线缆共用 `BlockPhysicsEvent` 入口；按 `mrtjp.projectred.integration.GatePart` 判定部件类型，计数、阀值、没收与公告各自独立，关闭时不做任何统计 |
| 代码结构 | `findWireTile` / `wireTileAt` / `removeWires` / `isWire` 泛化为 `findPartTile` / `partTileAt` / `removeParts` / `isPart`（多带一个部件类型列表参数），`collectWireTargets` / `hottestTile` 泛化为 `collectTargets` / `hottestTile`（多带计数表参数），线缆与逻辑门两条路径共用同一套逻辑 |

### 实测（server2：1.6.1，端口 25599；1.6.2 的逻辑门检测仅做构建验证，未实测）

| 场景 | 结果 |
|---|---|
| 多方块代理方块 ID | 插件解析得到 827，与探针插件一致 |
| 单条线缆 2 tick 时钟 | 10 秒窗口内只有「广播 / 已没收」两条记录，爆炸提示已移除 |
| 爆炸破坏范围（威力 10.0） | 没收点周围 5 格内方块变为空气，6 格外的平台仍为石头 |
| 爆炸实体伤害（威力 10.0） | 距没收点 2 格的无 AI 僵尸由 22 血降至 0 当场死亡，8 格外的僵尸仍有 21.08 血 |
| `AntiExplode.Enable: true` | 插件自爆仍能破坏方块，未被自身拦截 |
| 原版红石回归（限值 40） | 四节红石线在 2 tick 时钟下被清除，行为与 1.5.5 一致 |
| 单周期多目标（四个独立单元） | 前两次爆炸生成，其余目标只没收不炸，日志出现「本轮爆炸次数已达上限 2」 |

### 已知限制

- 只在 `BlockPhysicsEvent` 触发时统计，纯信号变化而无邻块通知的线缆网络（例如整条线只有两端有硬性连接）计数偏低。
- 爆炸威力沿用 TNT 口径，默认 10.0 会破坏没收点周围约 5 格地形并对附近实体造成高额伤害；需要保留地形时下调 `RedStone.Explosion.Power` 或关闭 `RedStone.Explosion.Enable`。

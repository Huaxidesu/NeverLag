# NeverLag 程序结构

> 更新时间：2026-11-10（1.4.5）。本文依据当前源码整理，供维护者与协作方快速建立全局认知。
> 语言与注释规范见同目录 `注释与Markdown规范.md`，部署与配置示例见仓库根 `README.md`。

## 1. 项目定位

NeverLag 是 Minecraft 1.7.10 服务端的 Bukkit 插件，目标运行环境为 GTNH 2.9.x 使用的
Crucible（Thermos 分支）。功能分两部分：

| 部分 | 来源 | 内容 |
|---|---|---|
| 防作弊与限流 | 上游 1.3.0 | 高频红石、刷怪率、登录频率、聊天与命令限速、掉落物清理等，见 `listener` 与 `task` 包 |
| 生物清理 | 本分支 1.4.x | 按类别定时清理活体实体，保留 Boss、命名生物、驯服宠物，清理后全服播报 |

默认分支 `legacy-1.3.0` 的基线源码由 1.3.0 成品 jar 经 CFR 0.152 反编译还原，1.3.1 与 1.4.x
为在此基础上自行维护的修改。上游 `master` 的 2.0-SNAPSHOT 重写版源码完整保留在 `master` 分支，
其 cleaner / fixer 未接入 `onEnable()`，也没有 1.7.10 的 NMS 分支，不可直接部署。

插件使用 `org.bukkit` 公开接口、服务端自带的 Bungee 聊天组件类与只读 NMS 反射，不修改模组代码。
`plugin.yml` 声明 `depend: [ProtocolLib]`，缺失时整个插件不会加载。

`AntiMotdPing` 与 `AntiPMM` 会注册。新增版本判断时应改用可比的版本号，不要沿用这套写法。

## 3. 数据流

### 3.1 定时清理与预警

预警与清理共用一个每秒执行的任务（`MobCleaner.reload()` 注册 `scheduleSyncRepeatingTask(20L, 20L)`），
用 `elapsed` 记已过秒数、`warned` 记本轮已播报到第几个预警点。

```
每 20 tick
  elapsed++
  while warned < warningAt.size() && elapsed >= delaySeconds - warningAt[warned]:
      播报 warningAt[warned]，warned++
  if elapsed >= delaySeconds:
      elapsed = 0；warned = 0；trigger(SCHEDULED)
```

预警与清理若各用独立任务，服务器卡顿会让两者前后错开若干秒。合并成一个任务后，
`while` 会把跳秒期间越过的预警点一次补播完，既不漏掉任何一条，播报时刻也与清理共用同一计数器。

`warningAt` 在读取配置时规整：丢弃非正数、重复值和不小于 `Delay` 的值，再从大到小排序。
把 `Delay` 调小时不需要回头修改预警列表。

预警播报走 `Bukkit.getServer().broadcastMessage(String)` 纯文本，与服务器上的垃圾清理插件
（ClearItem 3.3.0）使用同一条调用，不经过聊天组件与指令解析。

### 3.2 手动清理

```
/neverlag clear all|now|<实体 ID>
        │
        ▼
Mode.ALL（忽略类别开关） / Mode.NOW（按类别开关） / Mode.KEY（按实体键或中文名过滤）
        │
        ▼
与定时清理共用 trigger()
```

`Mode.KEY` 的匹配在 `MobCleaner.matches()` 中完成，接受四种写法：EntityList 键、去掉 modid 的键、
Bukkit 类型名、中文名。比较前统一小写，并把下划线替换为点、去掉空格，
所以 `THAUMCRAFT_WISP`、`thaumcraft.wisp`、`wisp` 命中同一实体。

### 3.3 三段式扫描与删除

实体增删必须在主线程执行，判定与查表可以异步，因此拆成三段：

```
主线程  trigger()
        running.compareAndSet(false, true)   拒绝重入，同一时间只有一轮
        遍历 getWorlds() → getLivingEntities()，复制引用
        并调用一次 getType()，预热实体类型缓存

异步    classify()
        逐个判定：Boss → 命名 → 驯服 → Exclude → 模式过滤 → 类别开关
        命中则查中文名 MobNames.resolve()，写入待清理列表

主线程  RemovalTask（每 tick 执行）
        单 tick 上限 BatchSize 只，且不超过 TimeBudgetMs 毫秒
        列表走完 → cancelTask → finish()
```

`RemovalTask` 以 `System.nanoTime()` 计算截止时间，两个上限任一到达即让出主线程，下一 tick 继续。
删除前再校验一次 `isDead()`、`isValid()`、`Player`、`NPC` / `MyPet` 元数据，
避免异步扫描到删除之间的状态变化造成误删。

单个实体判定抛异常时只跳过该实体，不影响整轮；世界读取失败写一条控制台警告。

### 3.4 判定顺序

顺序固定，Boss 必须排在命名判断之前：Boss 通常带自定义名，先判命名会把它算进「命名牌保留」，
播报里就会出现「命名牌 N 只」与实际不符。

| 顺序 | 判定 | 命中后的处理 |
|---|---|---|
| 1 | `MobClearConfig.isConfiguredBoss()` 或 `MobType.isBoss()` | 计入 Boss 保留，跳过 |
| 2 | `CustomName` 非空 | 计入命名保留，跳过（`ClearNamedHostile: true` 时敌对生物除外） |
| 3 | `Tameable#isTamed()` | 计入驯服宠物保留，跳过 |
| 4 | `Exclude` 名单 | 静默跳过，不计数 |
| 5 | `Mode.KEY` 的模式过滤 | 不匹配则跳过 |
| 6 | 类别开关 | `ALL` / `KEY` 忽略开关，`NOW` 按 `Clean` 段 |

美术装饰物（画、展示框、拴绳结）不是 `LivingEntity`，`getLivingEntities()` 不会返回；
`instanceof Hanging` 那道判断是防御性保留，防止将来更换取实体的方式。

### 3.5 播报

`ChatReport.broadcast()` 分两路：控制台永远打印，游戏内按配置与在线情况发送。

```
控制台：先打一行纯文本简报，再把悬浮明细逐行缩进 4 个空格打出
        │
        ├── Broadcast 为 false → 结束
        ├── 无在线玩家 → 结束
        ▼
ComponentSerializer.parse(json)
        │  解析失败 → 纯文本广播（后备）
        ▼
逐个玩家 player.spigot().sendMessage(BaseComponent[])
        │  该玩家失败 → tellraw <玩家名> <json>
        │  仍失败 → 该玩家收纯文本
        ▼
sent == 0（组件一条都没发出去）→ 纯文本广播
```

三条通道的取舍：

1. `player.spigot().sendMessage(BaseComponent[])` 直接把组件构造进聊天包，
   与 `broadcastMessage` 发的是同一个包，区别只是内容为组件；
2. `/tellraw <玩家名> <json>` 多经过一层指令解析，且 1.7.10 的 `tellraw` 只认单个玩家名，
   写 `@a` 会报「无法找到该玩家」而指令系统仍返回成功，因此不能靠返回值判断；
3. `Bukkit.broadcastMessage(String)` 一次广播全体，但字符串带不了 `hoverEvent`，只能作后备。

**1.7.10 的 Bukkit 没有 `Server.broadcast(BaseComponent)`**（该方法 1.8 才加入），
所以组件必须逐个玩家发送。日志行会区分通道：

```
[NeverLag] 简报播报：3 名玩家（组件直发 3，tellraw 0）
```

悬浮明细每类最多列 30 种（`MAX_NAMES_PER_TYPE`），超出写成「…另有 N 种」，
避免上万只生物时把聊天包撑大。

JSON 由 `ChatReport` 手工拼接，不依赖组件对象的序列化：颜色在 `splitLegacy()` 中从 `§` 代码
解析成颜色名，`hoverEvent` 固定写 `show_text` 加 `value` 字符串，与 1.7.10 客户端认的格式一致。
拼接结果在发送前由 `ComponentSerializer.parse()` 转成组件树，解析失败即整条降级为纯文本。

## 4. 配置结构

### 4.1 config.yml

上游原有配置，350 行，27 个顶层段。与生物清理相关的只有 `ClearEntity`：

| 键 | 说明 |
|---|---|
| `Enable` | 是否启用旧版实体清理任务 |
| `Delay` | 清理周期（秒） |
| `OnlyClearWhenLimit` | 仅在活体总数达到 `Limit` 时才执行 |
| `Limit` | 上面的数量阈值 |
| `Animals` / `Monster` / `Squid` / `Villager` | 四类是否清理 |

`mobclear.yml` 的 `Enable` 为 `true` 时，`ClearEntity` 的定时任务不再注册，
控制台打印「已启用新的生物清理（mobclear.yml），旧的 ClearEntity 定时任务不再注册」。
两套同时运行会把同一批生物清两次，播报也会重复。

> 上游遗留两处笔误，不影响运行：`Boat: fasle` 读取失败时按默认值 `false` 处理；
> `ClearItemFrame` 的键名与读取代码中的 `ClearItem.ItemFrame` 不一致，该开关恒取默认值。

### 4.2 mobclear.yml

生物清理的独立配置。分文件存放的原因是不动服务器上已调好的 `config.yml`：
1.7.10 的 `YamlConfiguration` 保存时会丢掉注释，覆盖旧文件的代价太大。

| 键 | 默认值 | 说明 |
|---|---|---|
| `Enable` | `true` | 定时清理总开关 |
| `Delay` | `1800` | 清理间隔（秒），读入时下限 5 |
| `WarningAt` | `[60, 10]` | 预警时间点（秒），空列表表示不预警 |
| `WarningMessage` | 见默认文件 | `%TIME%` 替换为剩余秒数 |
| `Clean.Hostile` / `Friendly` / `Neutral` | `true` | 定时清理的类别开关 |
| `BatchSize` | `200` | 每 tick 最多删除数量，读入时下限 10 |
| `TimeBudgetMs` | `4` | 每 tick 最多占用的毫秒数，读入时下限 1 |
| `ExtraHostile` / `ExtraFriendly` / `ExtraNeutral` | 空 | 把某个 Mod 生物挪到指定类别 |
| `Exclude` | 空 | 永不清理的实体，默认为空（村民、铁傀儡也会被清） |
| `Boss` | 42 项 | 额外保护的 Boss，见第 6 节 Boss 判定与名单 |
| `ProtectBossNamed` | `true` | 类名含 `Boss` 的一律保护 |
| `Broadcast` | `true` | 是否进行游戏内播报 |
| `Debug` | `false` | 把简报 JSON 与通道选择打进控制台 |
| `ClearNamedHostile` | `false` | 敌对生物带名字是否也清 |
| `Message` | 见默认文件 | 简报主文案，`%COUNT%` 为总数 |
| `NamedMessage` / `TamedMessage` / `BossMessage` | 见默认文件 | 保留说明，数量为 0 或置空则不显示 |

`Boss` 段写空列表时会回填内置的 42 项默认名单，无法通过清空列表取消全部保护。
要放宽保护范围，改用 `ProtectBossNamed: false`（只关第三条规则，前两条仍然生效）。

### 4.3 生物中文名表

`src/main/resources/mobnames_zh_cn.txt`（987 条）随 jar 打包，格式为 `键=中文名`，
同一实体同时写入带 modid 与去掉 modid 两种键。运行时只做查表，不做解析。

数据由 `tools/gen_mobnames.py` 从 GTNH 整合包自带的汉化中提取，优先级从低到高：
原版 1.7.10 的 `zh_CN.lang`、`mods/*.jar` 内的 `assets/<modid>/lang/zh_CN.lang`、
`config/txloader/forceload/*/lang/zh_CN.lang`、`____gtnhoverridenames_zhcn`。

`MobNames.resolve()` 的查找顺序：EntityList 键 → 去掉 modid 前缀的键 → Bukkit 类型名 →
取最后一个下划线之后的部分 → 都查不到时返回 EntityList 键（取不到则返回 Bukkit 类型名）。
因此 SpecialMobs 的 `SpecialMobs.HungryZombie` 没有单独汉化时会回退到「僵尸」，
有汉化时显示「饥饿僵尸」。

## 5. 命令清单

插件只注册一个命令 `NeverLag`，全部子命令都是 OP 判定
（`sender instanceof Player && !sender.isOp()` 直接返回），不使用权限节点。

| 命令 | 说明 |
|---|---|
| `/neverlag clear all` | 清理敌对、友好、中立全部生物，忽略类别开关 |
| `/neverlag clear now` | 按 `mobclear.yml` 的类别立即清理一次 |
| `/neverlag clear <实体 ID>` | 只清理该种生物，支持 EntityList 键、去 modid 键、Bukkit 类型名、中文名 |
| `/neverlag bosses` | 按类汇总世界生物，标出哪些会被保护 |
| `/neverlag who` | 列出 `getOnlinePlayers()` 与 `bukkit.broadcast.user` 订阅者 |
| `/neverlag reload` | 重新读取 `config.yml` 与 `mobclear.yml`，并重挂定时器 |
| `/neverlag gc` | 强制执行一次垃圾回收，输出回收量 |
| `/neverlag show` | 输出操作系统、CPU、进程与内存信息 |
| `/neverlag find display\|lore <关键字>` | 在在线玩家背包中搜索显示名或 lore 含关键字的物品 |

`onTabComplete` 只补全 `clear`、`reload`、`gc`、`show`、`find` 与 `clear` 的第二级参数，
`who` 与 `bosses` 未加入补全列表，需手工输入。

## 6. Boss 判定与名单

`MobType.isBoss()` 三条规则，命中任意一条即保护：

| 规则 | 判定方式 | 覆盖对象 |
|---|---|---|
| 1 | 实现 `net.minecraft.entity.boss.IBossDisplayData` | 1.7.10 的头顶血条只认这个接口，屏幕上方有血条的一定命中 |
| 2 | 实现 `net.minecraft.entity.IEntityMultiPart` | 末影龙、九头蛇、娜迦、雪女王、混沌守卫这类多部位实体 |
| 3 | 类名（含父类，最多回溯 24 层）含 `boss` | 没实现血条接口、名字却表明是 Boss 的模组生物，由 `ProtectBossNamed` 控制 |

规则 3 只比较类名（含父类）是否含 `boss`，转小写后匹配，因此 `EntityBossDragon`、
`EntityThaumcraftBoss`、`EntityTFBoss` 会命中；`KingBlueSlime` 这类名字不含 boss 的
只能靠名单命中。`IEntityMultiPart` 实现者中包含 `EntityTFBlockGoblin`、`EntityTFChainBlock`
这类技术实体，被一并保护，对清理结果无影响。

`Boss` 名单的匹配（`MobClearConfig.isConfiguredBoss()`）同时接受三种写法：
EntityList 键（`TwilightForest.Hydra`）、完整类名、简单类名（`EntityTFHydra`）。
比较时忽略大小写，`contains()` 允许配置值作为实体键的后缀匹配（`Hydra` 命中 `TwilightForest.Hydra`）。

## 7. 并发与线程

| 位置 | 线程 | 说明 |
|---|---|---|
| 计时器、预警、`trigger()` 快照 | 主线程 | Bukkit 调度器，每 20 tick |
| `classify()` | 异步线程 | 只读取快照与静态表，不触碰世界 |
| `RemovalTask` | 主线程 | 每 tick 分批删除，受 `BatchSize` 与 `TimeBudgetMs` 约束 |
| `ChatReport.broadcast()` | 主线程 | 在 `finish()` 中调用 |
| `NmsAccess.HANDLE_METHODS` | 双线程 | `ConcurrentHashMap` 缓存每个 CraftEntity 类的 `getHandle` 方法 |
| `MobNames.NAMES` | 启动时写入 | 加载完成后只读 |

重入保护用 `AtomicBoolean running`，`trigger()` 以 `compareAndSet` 抢占；扫描异常、删除完成、
插件停用时都会复位。定时器在 `plugin.isEnabled()` 为 `false` 时自行取消。

NMS 反射只做三件事，且都按类型而非方法名查找：`CraftEntity#getHandle`（CraftBukkit 自身方法，
不会被重映射）、`EntityList` 中返回 `String` 且接受 `Entity` 的单参数静态方法（运行期方法名为 SRG，
如 `func_75621_b`）、按类名逐级比较接口与父类。类名在 Crucible 下已反混淆为 `net.minecraft.*`，
因此比较写全名可行。

## 8. 与其他插件的关系

| 插件 / 模组 | 关系 |
|---|---|
| ProtocolLib | `plugin.yml` 声明为必需依赖；`AntiInvEditor` 用它的包监听 |
| ClearItem 3.3.0 | 负责掉落物清理与「大胃袋」功能；其普通播报使用 `broadcastMessage`，与生物清理的预警同一通道 |
| Essentials | `/give`、`/i` 等命令可能由它接管，与本插件无交集 |
| SpecialMobs / InfernalMobs | 会给生物自动起名；`ClearNamedHostile: false` 时这类生物全部保留 |
| NPC / MyPet | 实体带 `NPC` 或 `MyPet` 元数据时跳过，不参与清理 |
| AEMobile（模组） | 播报走服务端聊天包，AEMobile 的聊天抓取会一并投递到手机端 |

## 9. 开发工具链

| 工具 | 用途 |
|---|---|
| `build.sh` | 用 Zulu 8 的 `javac` 与服务端的 `Crucible.jar`、`ProtocolLib.jar` 编译打包，产物 `build/NeverLag<版本>.jar` |

版本号在两处维护：`build.sh` 的 `VERSION` 与 `src/main/resources/plugin.yml` 的 `version`。

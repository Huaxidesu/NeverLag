## 2026-11-11：1.5.1

| 模块 | 内容 |
|---|---|
| 精英怪 | 新增 `ClearInfernal`（默认 true）：读实体持久 NBT 的 `InfernalMobsMod` 判定精英怪，命中后无视自定义名照常清理 |
| 诊断 | 新增 `/neverlag named`：按名字聚合列出被「命名保留」挡下的生物，并标出是否带精英怪标记 |

### 实测（server2：1.5.1，端口 25599）

| 场景 | 结果 |
|---|---|
| 带 `ForgeData.InfernalMobsMod` + 名字的僵尸 | `/neverlag named` 标为 `[精英]` |
| 只带名字的僵尸 | 标为 `[普通]`，`clear now` 后仍存活 |
| `clear now` | 清理完成 3 只，精英怪被清，玩家命名的僵尸保留 |

### 已知限制

- NBT 读不到时（其它服务端实现）一律按「不是精英怪」处理，此时只能靠 `ClearNamedHostile` 或名单。

## 2026-11-11：1.5.0

| 模块 | 内容 |
|---|---|
| 计时 | 由「累计任务执行次数」改为系统时间戳比对，`Delay` 成为真实秒数，掉 TPS 不再拉长周期 |
| 诊断 | 新增 `/neverlag status`：开关、周期、本轮已过、下一轮时间、上次清理结果 |
| 日志 | 防 ALL-U-WANT 的 `ClassNotFoundException` 堆栈只在 `Debug: true` 时打印 |

### 实测（server2：1.5.0，端口 25599）

| 场景 | 结果 |
|---|---|
| `Delay: 70` + `reload` | 23:40:15 重载，23:41:25 准点清理（误差 0 秒），状态里下一轮同步为 23:42:35 |
| 恢复 `Delay: 1200` | 状态显示「本轮已过 0 秒，下一轮还有 1200 秒」 |
| 启动噪音 | 日志中不再出现 NeverLag 的 `ClassNotFoundException` 堆栈 |

### 已知限制

- 生产日志显示清理周期为 1800 秒而非常用的 1200，说明生产上仍在用 jar 内置默认配置。

## 2026-11-10：1.4.9

| 模块 | 内容 |
|---|---|
| 神秘时代傀儡 | `MobType.isThaumcraftGolem()` 按基类 `EntityGolemBase` 判定，傀儡与旅行箱固定保留，不受配置影响 |
| 出厂配置 | `mobclear.yml` 的 `Exclude` 预先写入 `Thaumcraft.Golem`、`Thaumcraft.TravelingTrunk` |
| 排查命令 | `/neverlag bosses` 把傀儡与旅行箱一并标为 ★，表头文字改为「受保护」 |

### 实测（server2：1.4.8 + 新配置，端口 25599）

| 场景 | 结果 |
|---|---|
| `Exclude: []` 时 `clear now` | 清理完成：1 只，被清的是未命名的傀儡 |
| 还原 `Exclude` 后 `clear now` | 没有符合条件的生物，2 只傀儡（含 1 只命名）与 1 只旅行箱全部保留 |

### 已知限制

- 代码层的固定保留要重启服务端才生效；仅换配置时，保护由 `Exclude` 名单承担。
